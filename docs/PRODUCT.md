# LiteCool S1 —— 产品总览（整个产品的架构）

> 本文档回答"这个产品到底是什么、由哪几层构成、文档和代码各归何处"。
> 它是全项目文档体系的入口；各层细节由它链接出去，不在这里复制。

## 1. 产品 = 两层系统

```
┌─────────────────────────────────────────────────────────┐
│  L1 实物产品：LiteCool S1 桌面小空调                        │
│  TEC 半导体制冷 · 双风道 · 出风温度数显 · 导风板扫风          │
│  双 SKU：Cool ¥119–129 / Pro ¥159                        │
│  → design-spec.md（产品定义唯一事实源）                     │
├─────────────────────────────────────────────────────────┤
│  L2 研发操作系统：把 L1 从调研做到开模的流水线                 │
│  S0–S9 阶段 + 数据闸 + 工作台（六视图控制室）                 │
│  → docs/code-architecture.md + pipeline/ + workbench/     │
└─────────────────────────────────────────────────────────┘
```

两层的关系：L2 的每个阶段都在为 L1 消除一类不确定性——S1 竞品（市场）、S3 专利（法律）、S4/S5 供应链与成本（商业）、S6/S8 建模与手板（物理）、S7 决策（人）。**工作台是 L2 的控制室，也是 L1 的"活文档"。**

## 2. 实物产品一页（L1 摘要）

- 品类：桌面小空调（不是风扇）——"给工位/宿舍/床头一个人降温"
- 三大差异化：① 真 TEC 制冷且**降温看得见**（出风温度实时数显，13 款竞品无人做）；② 双风道热架构（冷/热风道物理隔离，ADR-1）；③ 每个结构件可对接真实工厂（BOM 8 模块全覆盖）
- 形态：A 桌面挂机（已选定，B/D 备份）；工程装配体 40 件 DFM 级
- 关键文档：`design-spec.md`（产品定义）→ `architecture/product-architecture.md`（系统架构）→ `requirements/requirements-brief.md`（需求基线）

## 3. 研发流水线一页（L2 摘要）

S0 需求 → S1 竞品 → ∥S2 形态/S3 专利/S4 供应链 → S5 成本 → S6 建模 → S7 人类验收 → S8 手板 → S9 FTO+开模。
当前状态：S0–S6 ✅，S7 决策已录（Q1=A/Q2 砍风冷款/Q3 询价+¥129 兜底），S8 待手板，S9 未开始。
详见 `docs/code-architecture.md`；状态板 = 工作台①；计划 = `IMPLEMENTATION_PLAN.md`。

## 4. 文档体系（产品文档架构）

| 层 | 内容 | 位置 | 读者 |
|---|---|---|---|
| 门面 | 项目是什么、亮点、快速开始 | `README.md` | 外部访客 |

| 需求与定义 | 需求基线、产品定义书 | `requirements/`、`design-spec.md` | 决策者/工程师 |
| 架构 | 硬件系统架构、代码/流水线架构 | `architecture/`、`docs/code-architecture.md` | 工程师 |

| 工程 | 装配体脚本与 notes、图鉴管线、AI 皮肤管线 | `cad/` | 结构/制造 |
| 研究 | 竞品、专利、1688 供应商与询价记录 | `research/` | 全员（证据层） |

## 5. 包架构（repo 目录职责与依赖规则）

```
puzhi-fan/
├── design-spec.md            ← L1 产品定义（唯一事实源）
├── IMPLEMENTATION_PLAN.md    ← 阶段计划（随做随更，完成即归档）
├── requirements/             ← 需求基线
├── architecture/             ← L1 硬件系统架构
├── design/                   ← 工业设计（方向稿/prompt/图鉴源）+ 前端设计真源(workbench/)
├── research/                 ← 证据层：竞品/专利/1688/评价原始抓取（只追加，不改写历史）
├── data/                     ← 结构化事实层：bom/forms/decisions/闸报告（生成器写，工作台读）
├── cad/                      ← 全部 3D：装配体脚本+GLB+渲染+图鉴管线+AI 皮肤管线
├── concepts_v2/              ← codex 概念图成品（concepts/ 为 v1 存档）
├── rfq/                      ← 商业外联：询价包/NDA/受控外发包
├── pipeline/                 ← L2 编排：阶段注册/数据闸/状态板/CLI
├── workbench/                ← L2 控制室：src(ES-module 组件)/vendor/dist
├── docs/                     ← 总览/代码架构/S8 计划/审计 handoff
├── dashboard/                ← 旧工作台（冻结，见 LEGACY.md）
└── images/                   ← 通用图片素材
```

依赖规则：
1. `research/` 与文档层是**源头**；`data/` 是源头的结构化（只能由脚本/明确的人工编辑写入）；`workbench/` 只读 `data/` 与 `research/`，禁止反向写。
2. 生成物（dist、renders、GLB）必须由脚本可重生；脚本与生成物同目录共存时，notes 说明重生命令。
3. 新增目录 = 先在此表登记职责再建（防包腐化）。
4. 归档纪律：作废物显式标记（`_DEAD` / `LEGACY.md`），不静默删除（审计链需要）。
