# 工作台重设计 · Phase 0 文字合同（v1，2026-08-29）

> 本合同是 Phase 1 出稿的唯一输入；出稿只许从本合同生成，禁止自由发挥。
> 判断权归属：方向好不好看 = Owner 的眼睛；落没落地 = 机械测量；agent = 翻译者+验证者。

## 1. 范围与非目标

**范围**：LiteCool S1 工程工作台六个视图（① 流水线总览 ② 竞品分析 ③ 形态对比 ④ 3D拆分+供应链 ⑤ 专利规避 ⑥ 需求与决策）的 layout/UI/UX 重设计。桌面 1440px+ 优先。
**非目标**：不做营销官网；不做移动端适配；不引前端框架/构建链（保持 Python 字符串模板 + 单文件 + Three.js CDN）；不改数据层（data/、pipeline/）与闸门逻辑；不改变台本质——它是**工程验收工具**，不是展示页。

## 2. 数据可见性规则

- 全部内容只读（工作台无写操作），无权限分层。
- 每个数据元素只有三种出身：**有出处**（data/*.json、research/ 字段，卡片上带数据源标记）/ **静态文案**（说明性文字）/ **待补**（数据缺口——必须渲染为具名占位，注明"缺什么、什么动作会填上"，禁止伪造中间态）。
- 语义色纪律不可动：绿=已核验/实测，黄=候选/待补，红=风险/阻塞。

## 3. 布局合同

### 3.1 全局骨架

- **顶栏**（sticky，≤56px）：左 = 产品名 + 数据生成时间；中 = 六视图分段导航（唯一导航控件）；右 = 语义色图例。
- **页面级滚动**，Tab 内部**禁止内嵌滚动**（当前 ④ 的零件列表内嵌滚动 = 违反，必须改）。
- 内容最大宽度 1440px 居中；首视口（900px 高）必须露出该视图的**核心判读区**（见 3.2）。

### 3.2 首视口合同（每视图一屏能干什么）

| 视图 | 首视口必须完成的事 |
|---|---|
| ① 流水线 | 一眼读完 S0–S9 状态；阻塞项（当前=用户动作类）置顶独立区，不埋在阶段卡里 |
| ② 竞品 | 卡片网格首行可见；顶部一行筛选（品类/档位/数据完整度）；空壳款灰卡"待补" |
| ③ 形态对比 | A/B/D 三卡一屏看全（W1/W2 收进"探索"折叠区）；每卡大图为主角，评分收敛一行 |
| ④ 3D拆分 | **3D 查看器占首视口 ≥60% 高度**（当前被零件列表挤压过矮=违反）；工具条（形态切换/爆炸/透视/标注）收进查看器顶边一行；零件清单在查看器下方整宽横排分组 |
| ⑤ 专利 | 方向评级表 + 逐方向规避要点首屏可读；全文链接下沉 |
| ⑥ 需求决策 | 决策时间线在上（最新决策置顶），需求追溯表在下 |

### 3.3 信息层级纪律（当前最大病灶）

- 每视图**有且只有一个视觉锚点**（① 阻塞项 ② 卡片网格 ③ 形态大图 ④ 3D 查看器 ⑤ 评级表 ⑥ 时间线）；
- 卡片内信息分三级：主张（大）/ 关键参数（中）/ 备注来源（小、折叠或弱化）——禁止全字号均质；
- banner 只放一行结论+一个链接，禁止文字墙（当前 Q1 banner 三行 = 违反）；
- 长内容一律折叠进 `<details>` 或二级区，首屏只留判读所需。

## 4. 组件清单（registry，禁止同一需求两个实现）

| 组件 | 用途 | 状态 |
|---|---|---|
| 分段控件 segmented | 六视图导航 + 视图内所有"切换"（形态切换/媒体分层/模式开关） | **统一为一种控件语言**（当前 ③④⑤ 三套切换 UI = 分叉，必须合并） |
| 状态徽章 badge | ok/warn/risk/待补 四态 | 保留，统一尺寸字重 |
| 数据卡 card | 竞品卡/形态卡/阶段卡 | 一种卡体系三种密度 |
| 星级条 stars | 六维评分 | 收敛单行，悬浮出注记 |
| 3D 查看器 viewer | GLB + 工具条 | 工具条并入查看器边框，不外溢 |
| 空态占位 ph | 待补/未产出 | 具名+原因+动作 |
| banner | 结论行 | ok/warn/risk 三色，一行 |

## 5. UX 行为规则

- **只读工作台**：无写操作，无乐观态问题；数据新鲜度（生成时间）顶栏常驻。
- **加载态**：GLB 未加载时查看器显骨架屏+进度文字；加载失败给重试，不白屏。
- **空态**：给"为什么空+能做什么"（如"形态 B GLB 待产出——S6 建模中"）。
- **键盘**：Tab 可达所有控件，Enter/Space 激活，focus-visible 全站统一。
- **一致性**：同一种交互语义只许一种控件（见组件表 segmented 条目）。

## 6. 文案语调

quiet operations：陈述事实，无感叹号，无营销词，无"非常好/完美"。结论词只用：已核验/待补/风险/阻塞/已选定。

## 7. 当前病灶清单（本次重设计必须逐条核销）

1. 视图无视觉锚点，信息均质平铺
2. 切换控件三套语言（③形态 pill / ④形态按钮 / 媒体分层按钮）
3. ④ 3D 查看器过矮、被零件列表内嵌滚动挤压
4. 卡片内主张/参数/备注同字号同权重
5. banner 文字墙
6. 零件清单/BOM 表在窄口下挤压换行失控
7. 数据新鲜度不可见（生成时间埋在 banner 里）

## 8. Phase 1 出稿方向（三候选，Owner 选一冻结）

- **方向甲「工程极简」**：Linear/Vercel 式——深灰或米白底、发丝线、单强调色、密集但克制
- **方向乙「产品画廊」**：Apple 产品页式——大留白、大图、少即是多、密度低
- **方向丙「文档排印」**：Notion/学术文档式——左栏导航、正文流、表格为主、打印感

## 9. 前端架构合同（v1.1 补充，2026-08-29——替代 §1"不引前端框架"非目标）

**问题认定**：现实现是 `build.py` 字符串拼接的 135KB 单文件巨石——无组件、无状态层、视图/数据/样式三逻辑混合，不是架构。

**选型决策：无构建链的 ES-module 组件架构**（不引 Vite/React/npm）。理由：① 本机工程工具，离线可用优先；② 现代浏览器原生 ES modules + CSS 自定义属性已能支撑组件化，零新依赖符合项目工具纪律；③ 复杂度上限可控（六只读视图），React 生态的构建链成本超过收益。若未来出现写操作/多用户/实时数据，再评估迁移（目录结构按可迁移设计）。

```
workbench/
  src/
    main.js               ← 启动 + hash 路由（六视图）
    state.js              ← 数据加载（fetch data 快照）+ 极简 store（订阅通知）
    lib/dom.js            ← h() 元素构建助手（~30 行，替代字符串拼 HTML）
    components/           ← 与 §4 registry 一一对应，每组件一个文件
      segmented.js  badge.js  card.js  stars.js  banner.js  empty.js
      glb-viewer.js       ← Three.js 封装（懒加载单例）
      assembly-viewer.js  ← 爆炸/透视/标注/BOM 卡（现 initAssembly 迁入重构）
    views/                ← 六视图各一文件：pipeline.js competitors.js forms.js
                          assembly.js patent.js decisions.js
    styles/
      tokens.css          ← 设计令牌（Phase 2 spec 的唯一实现出口：色/字阶/间距/圆角）
      base.css  components.css  views.css
  vendor/three/           ← three.module.js + GLTFLoader + CSS2DRenderer 本地固化
                          （替代 CDN import map——离线可用、版本钉死）
  build.py                ← 只做三件事：validate → 把 data/*.json 快照拷进 dist/data/
                            → 拷贝 src/vendor 到 dist（**不再生成任何 HTML**）
  dist/                   ← 纯静态站：index.html(壳,~40 行) + src + data 快照
```

**数据流**：`pipeline validate → data/*.json → build.py 快照 → state.js fetch → store → views 订阅渲染`。HTML 里没有任何业务字符串；视图只读 store，不直接读文件。

**与 Phase 2 的衔接**：tokens.css 由 spec 测量值填充（脚本生成 `:root{}` 块），组件 CSS 只许引用令牌变量，禁止硬编码色值/字号——规格变更只改 tokens。

**机械验证**：① `node --check` 全部 js 语法闸（或浏览器 console 无错截图）；② ego-browser 逐视图截图 + 关键 computed style 像素采样（证明 tokens 生效）；③ GLB 查看器交互 DOM 断言。
