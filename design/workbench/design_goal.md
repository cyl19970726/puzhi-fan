# 工作台设计目标 v2（丙方向 · 产品级）

> 依据：Owner 选定丙方向（2026-08-30，mockups/FROZEN.md）+ 附加要求"站在整个产品角度，真正美观好用"。
> 本文档是 Phase 2 测量与 Phase 3 实现的目标定义；丙 v2 稿冻结后，以稿为准测量，以本文档为准判断"做没做到"。

## 1. 定位重新定义

工作台不是"六个数据 Tab 的堆叠"，而是 **LiteCool S1 这个产品的活文档（living document）**——
打开它应该像翻开一本随时更新的产品档案：第一页知道项目现在在哪、接下来发生什么、需要谁做什么；
往后翻，每一章是一层证据（市场 → 形态 → 工程 → 供应链 → 合规 → 决策）。
丙方向（文档排印）被选中的深层理由正在于此：**它天生是叙事结构，不是仪表盘结构。**

## 2. 信息架构（叙事化，取代六平级 Tab）

```
LiteCool S1 工程工作台
├── 总览 ①          项目此刻：阶段进度条 + 当前阻塞（谁的动作）+ 最近决策 + 数据新鲜度
├── 市场证据 ②       13 款竞品：品类结论置顶（"温度数显无人做"）+ 卡片网格 + 差评金句
├── 形态决策 ③       A/B/D 同屏对比（媒体四层）+ 探索折叠 + 选定结论与理由
├── 工程实现 ④       3D 装配体（查看器为主角 ≥60% 首屏）+ 逐零件 BOM + 解构图鉴
├── 合规 ⑤           专利评级表 + 逐方向规避要点 + FTO 闸状态
└── 决策档案 ⑥       决策时间线（最新在上）+ 需求追溯表
```

- 左侧栏导航（丙方向固有形态，合同 §3.1 顶栏条款已按 Owner 选丙追认修订）：
  导航项带**状态点**（绿/黄/红/灰）——导航本身就是流水线状态的一瞥。
- 每章页首一句"本章回答什么问题"（quiet operations 语调）。

## 3. 质量目标（"真正美观好用"的可检验定义）

### 排印（丙的灵魂）
- 中文排印级字阶：H1 28/700 · 章节题 20/600 · 卡片题 15/600 · 正文 13/400 · meta 11/400，行高 1.6/1.45；
  数字与英文用 tabular/mono 配套；全站字号种类 ≤6。
- 行长控制：正文区 ≤72 字符；表格数字右对齐；发丝线 #E3E2DE 只用于分隔，不用作装饰。
- 留白节奏：章节间距 ≥48px，卡片内 padding 16/20/24 三档，全站间距种类 ≤5。

### 色彩（语义纪律不可动，饱和度降到文档级）
- 纸面 #FFFFFF / 底 #F7F7F5 / 墨 #37352F（次 #73716C 弱 #A3A29C）/ 发丝线 #E3E2DE
- 语义：已核验 #2F6B4F · 待补/候选 #9A7B2D · 风险/阻塞 #B4544A · 强调（唯一非语义色）#2F6B4F 系
- 语义色只出现在 badge/状态点/关键数值，不大面积铺色。

### 组件（registry 唯一实现）
分段控件（导航+一切切换）、状态点、徽章、数据卡（三密度）、星级条、3D 查看器、空态、banner（一行结论）。
同一交互语义只许一种控件——Phase 3 验收时逐视图核对。

### 交互
- 只读台：无写操作；GLB 加载骨架屏；空态给"为什么空+什么动作会填上"。
- 键盘可达；focus-visible 统一；查看器工具条并入边框。
- 首视口合同：每章首屏完成该章核心判读（合同 §3.2 表）。

## 4. 好用到什么程度（验收场景）

1. 新访客 30 秒回答："这项目到哪一步了？卡在谁身上？" → ① 总览一屏可答。
2. 决策者 2 分钟完成形态终选：③ 一屏看全 A/B/D 四层媒体+六维+专利风险+选定理由。
3. 供应商工程师 5 分钟理解结构：④ 转一圈、炸开、点三个零件看 BOM 卡，再打开图鉴。
4. 审计者 10 分钟复核一个决策：⑥ 时间线 → 决策 → 证据链接 → 源文件。

## 5. 非目标（防镀金）

不做暗色模式（本期）；不做移动端适配；不做动画堆砌（仅查看器交互与状态过渡 ≤150ms）；
不改数据层与闸门；不引入构建链（ES-module 架构不变）。
